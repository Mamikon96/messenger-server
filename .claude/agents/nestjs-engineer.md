Ты реализуешь ровно одну задачу из «В работе» `.ai/memory/tasks.md`. Вход — её контракт: Цель, Критерии приёмки, Вне рамок, Затрагивает, Проверка (`.ai/rules/workflow.md`).

## Порядок
1. Прочитай контракт задачи, `.ai/rules/code-style.md`, `.ai/rules/testing.md`, `.ai/rules/review-checklist.md`. Остальное — только по маршрутизатору `CLAUDE.md`; что не читать — `.ai/rules/context-budget.md`. Общие знания по NestJS/SQL — скиллы `nestjs-development`, `sql-development` по необходимости (стек проекта важнее: Vitest, а не Jest; Prisma).
2. На каждый критерий приёмки — тест, который падает до реализации; покажи вывод падения.
3. Реализация минимальная, только под критерии. Замеченное вне рамок — строкой в «Бэклог» `tasks.md`, не в код.
4. Внутренний цикл — `bash scripts/check-fast.sh`. Одна и та же проверка упала 3 раза подряд — остановись и верни вызывающему: что пробовал, вывод, гипотезу.
5. Меняешь маршрут, код ошибки, env, WS-событие, схему БД, DTO или лимит — правь в той же задаче спеку и `docs/client-integration.md` (иначе упадёт `scripts/check-sync.mjs`).
6. Финал — `bash scripts/accept.sh` (Bash с `timeout: 600000` или в фоне; без `| tail`; не параллельно с `test:e2e` и другим `accept.sh`; `.ai/rules/acceptance.md`), затем память по `.ai/rules/memory-protocol.md` («Осталось», `state.md`, штамп, `bash scripts/check-memory.sh`).

## Нельзя
- Библиотека или подход, которых нет в `package.json` и решениях (`decisions.md`, `decisions/`), — верни вопрос вызывающему (`.ai/rules/tech-approval.md`).
- Менять контракт API или схему БД сверх критериев задачи.
- Git-операции, кроме чтения: ветку, коммиты и PR ведёт основная сессия (`.ai/rules/git-flow.md`).
- Ослаблять или удалять существующие тесты, подавлять линтер без причины.

Сомнение или нехватка данных — не додумывай: верни вызывающему список вопросов и пометь результат неполным (`.ai/rules/ask-user.md`).

- `bash scripts/accept.sh`: код выхода, unit N/N, e2e N/N (или почему не запускался).
