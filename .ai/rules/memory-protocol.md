# Протокол памяти
Читать: перед началом работы над задачей разработки (шаг «Старт») и перед ответом пользователю после любых изменений (шаг «После правок»).
Описание файлов памяти и их форматов — `.ai/memory/README.md`.

## Старт (читать минимум)
- Всегда: `.ai/memory/tasks.md` (сводку «В работе» даёт SessionStart-hook). Задача из бэклога → в «В работе» с контрактом (`workflow.md`), затем `bash scripts/git-task.sh start BE-NN <slug>` (`git-flow.md`).
- Остальное — только по необходимости (таблица «когда читать» в `.ai/memory/README.md`): `state.md` — баг/регрессия/известные проблемы; `architecture.md` — новые модули, правка структуры или схемы БД; `decisions.md` — архитектурный выбор или новая технология (искать по заголовкам, не читать целиком); `tasks-archive.md` — только `grep`.
- Факты из памяти перепроверять по коду: расхождение = память неверна, исправить.

## После правок (до ответа пользователю)
После ЛЮБЫХ изменений (код, тесты, конфиги):
1. `tasks.md`: промежуточный прогресс → «Осталось»; новая найденная работа → «Бэклог»; правка вне задач → отдельная запись («В работе» или «Сделано»).
2. `state.md` — по сверке с кодом, каждая проблема с путём к файлу; `architecture.md` — если изменилась структура.
3. Штамп `> Проверено: ГГГГ-ММ-ДД @ <sha>[+dirty]` (дата — `date +%F`, sha — `git rev-parse --short HEAD`; пока нет git — `@ no-git`).
4. `bash scripts/check-memory.sh` — включает жёсткую сверку кода со спекой, `docs/client-integration.md`, архитектурой и ссылками на решения/задачи (`scripts/check-sync.mjs`). Менял контракт (маршрут, код ошибки, env, WS-событие, схему БД, DTO, лимит) — обнови код, спеку и `docs/client-integration.md` в той же задаче; иначе проверка упадёт.
- Закрытая задача переносится из «В работе» в начало `tasks-archive.md` с датой — только при выполнении `acceptance.md`.
- Запись в `decisions.md` — сразу после выбора пользователя, не раньше (`tech-approval.md`); без выбора не писать.
- Не дублировать в памяти то, что очевидно из кода или git.

## Итог
Финальный отчёт — по шаблону `.ai/rules/report-format.md`, строится из обновлённых файлов памяти.
