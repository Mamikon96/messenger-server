# Не придумывать — спрашивать
Читать: всегда, любому агенту (основная сессия, `*-engineer`, `*-reviewer`, `solution-architect`, `system-analyst`, `task-planner`, фоновые). Правило жёсткое, действует поверх любых других.

1. **Сомнение или нехватка данных → вопрос пользователю.** Если для решения задачи не хватает информации, требование двусмысленно, есть несколько разумных трактовок или ты в чём-то не уверен — остановись и спроси. Не додумывай, не угадывай, не подставляй «разумные значения по умолчанию», не заполняй пробелы собственными допущениями.
2. **Что нельзя придумывать:** требования и критерии готовности, тексты и поведение UI, имена и форматы данных, значения конфигов, причины багов, факты о коде и проекте (проверяй по коду, а не по памяти), результаты команд и тестов.
3. **Как спрашивать:** основная сессия и агенты с доступом к `AskUserQuestion` — через него (2–4 варианта, рекомендация первым пунктом, если она есть; открытый вопрос — обычным текстом). Вопросы — до начала работы, а не после «чтобы не ждать».
4. **Агент без возможности спросить** (только чтение, фоновый, нет `AskUserQuestion`): не продолжать на догадке. Остановиться на спорном месте, вернуть вызывающему список вопросов (что неясно, чего не хватает, какие есть варианты) и пометить результат как неполный. Основная сессия обязана переадресовать эти вопросы пользователю, а не отвечать за него.
5. **Что можно без вопроса:** то, что однозначно следует из запроса, `CLAUDE.md`, `.ai/` или кода, и уже принятые решения (`decisions.md`). Не спрашивай очевидное и не переспрашивай согласованное — вопрос нужен там, где есть реальная неопределённость.
6. **Ответ получен** — действуй по нему; если он порождает решение по технологии/подходу, дальше `tech-approval.md`.
