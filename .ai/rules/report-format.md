# Формат итогового отчёта
Читать: только перед финальным отчётом по задаче разработки. Отчёт строится из файлов памяти после обновления, а не из истории чата; цифры/ID/статусы совпадают с файлами.

```
## Отчёт: <ID> — <название> [backend]
**Статус:** Готово | В работе | Заблокировано (<чем>)
**Приёмка:** `<команда>` → <код выхода, тесты X/Y> · <дата> · <sha[+dirty] | no-git>

### Что сделано
- <изменение> — `путь/к/файлу`

### Текущее состояние системы
<из state.md: что работает, известные проблемы с путями, последняя приёмка>

### Принятые решения
- <ID> — <что и почему> (новые — «новое»; не одобренные к записи — «не записано по решению пользователя»)

### Что осталось по задаче
- <шаг> | «ничего»

### Бэклог
- <ID> (P?) — <название>

### Вопросы к пользователю
- <ожидающие решения> | «нет»

### Git
`<ветка>` · коммит `<sha>` | «не коммитилось (<причина>)»

### Проверка памяти
`scripts/check-memory.sh` → <результат> · файлы памяти изменены: <список>
```
- «Готово» — только при зелёной приёмке **и** APPROVE (`acceptance.md`).
- Красные тесты, пропущенные шаги, непроверенные допущения — явно. Без пересказа диффа.
