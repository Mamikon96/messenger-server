## Бэклог
- **BE-47 (P3)** Нет IP-лимита и лимита на успешные смены пароля у `POST /api/me/password`: каждый запрос стоит два argon2 (проверка + хэш), успех сбрасывает счётчик по логину, поэтому владелец сессии (или украденная сессия) может гонять сервер без `429`. Рассмотреть `AuthRateLimitGuard` или лимит на пользователя; связано с BE-45 (защита главного потока от argon2). Найдено ревью BE-39.
- **BE-46 (P2)** NUL и другие управляющие символы во входном тексте (имена `firstName`/`lastName`, названия чатов, сообщения, логин/пароль) → Postgres не принимает `0x00` в `text`, ожидается `500`. Сначала проверить воспроизведением, что это действительно `500`; затем решить код ответа (вероятно, `400 validation_failed` + `details` `invalid_format` там, где есть `details`) и набор запрещённых символов — вопрос пользователю. Найдено ревью BE-38.
- **BE-45 (P2)** Защитить главный поток от argon2 (BE-D38): по замеру `system-analyst` 2026-10-14 (Node v24.15, 8 ядер) асинхронный `crypto.argon2` при m=19456, t=2 около 40–50 мс на вызов выполняет в главном потоке, потолок ~20 хэшей/с на процесс, event loop при таком потоке занят почти полностью; `UV_THREADPOOL_SIZE` не влияет. Перемерить на целевом железе и версии Node, затем выбрать: глобальный лимит хэшей в секунду → `429 rate_limited` + `Retry-After` или `worker_threads` с ограниченной очередью (новый подход — `tech-approval.md`). Зависит от: BE-44.
