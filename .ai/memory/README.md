# Память проекта для AI

Проект — только backend (frontend — отдельный репозиторий `messenger-client-react`, SH-D04). Общий индекс — `.ai/README.md`; правила работы с памятью — `.ai/rules/memory-protocol.md`.

```
.ai/memory/
  README.md              # этот файл
  decisions.md           # решения проекта (SH-Dxx — сквозные, BE-Dxx — backend)
  product-agreements.md  # соглашения по продукту и бэкенду
  state.md  tasks.md  tasks-archive.md  architecture.md
```

## Файлы
| Файл | Что хранит | Когда читать | Как обновлять |
|---|---|---|---|
| tasks.md | В работе (одна задача с контрактом, `.ai/rules/workflow.md`) / Бэклог | всегда при задаче разработки | Двигать задачи между секциями; закрытую — в архив |
| tasks-archive.md | Сделано: дата, результат, приёмка, ревью | только `grep` по ID или теме | Только добавлять, новые записи сверху |
| state.md | Текущее состояние, известные проблемы (с путями к коду), последняя приёмка, фокус | баги, регрессии, выбор следующей задачи | Перезаписывать целиком только после сверки с кодом |
| architecture.md | Карта модулей, потоки данных, схема БД | новые модули, правка структуры/схемы | Править при изменении структуры |
| product-agreements.md | Цель, рамки и соглашения по продукту, архитектуре и бэкенду | проектирование контракта API/событий, реалтайм, серверное хранение | Менять только по решению пользователя (запись в `decisions.md`) |
| decisions.md | Решения: что, почему, альтернативы (общие `SH-Dxx`, backend `BE-Dxx`) | процесс/память, архитектурный выбор, новая технология (искать по заголовкам `## SH-Dxx` / `## BE-Dxx`) | Только добавлять в конец |

Контракт auth для этого проекта задан на стороне frontend: файл auth-contract.md в памяти репозитория `messenger-client-react` (`/home/mako/Projects/react/messenger-client-react/.ai/memory/auth-contract.md`). Своего `contracts.md` нет — контракты API/событий проектируются здесь (BE-03).

## Правила актуальности и корректности
- Первая строка после заголовка в `state.md`, `tasks.md`, `architecture.md`: `> Проверено: ГГГГ-ММ-ДД @ <git sha>[+dirty]` — дата и коммит, на которых факты сверены с кодом. Без git — `@ no-git`. Пишет **только** `scripts/stamp-memory.mjs` после успешной `bash scripts/check-memory.sh`; ручная правка заблокирована `scripts/hooks/protect.mjs` (SH-D19).
- Каждое утверждение о проблеме/состоянии содержит путь к коду в обратных кавычках и проверено чтением кода, `grep` или запуском — не по памяти и не по прошлой записи.
- Исправленное из «Известных проблем» удаляется (история — в git и `tasks-archive.md`).
- Задача в «В работе» содержит контракт с блоком «Осталось» (проверяет `scripts/check-sync.mjs`); запись в архиве — дату и результат приёмки.
- ID: задачи `BE-NN`, решения `BE-DNN` / `SH-DNN`. ID не переиспользуются (в том числе после удаления задачи).
- Даты — абсолютные `ГГГГ-ММ-ДД`. Не хранить секреты и то, что очевидно из кода/git.
- Механическая проверка: `bash scripts/check-memory.sh` (входит в `bash scripts/accept.sh`). Она же запускает `scripts/check-sync.mjs`: **код — источник истины**, любое расхождение кода со спекой (`docs/superpowers/specs/`), `docs/client-integration.md`, `architecture.md`, `.env.example`, ссылками на `BE-Dxx`/`SH-Dxx`/`BE-NN` — ошибка, приёмка не проходит. Меняешь маршрут, код ошибки, переменную окружения, WS-событие, схему БД, DTO или лимит — правь код и документы в одной задаче. Среди проверяемых фактов — коды `error.details[].code` (тип `ValidationCode` в `src/common/app-error.ts` против таблицы подраздела «Коды details» в `docs/client-integration.md` §1.3). Добавил новый вид фактов, которые должны совпадать, — расширь `scripts/check-sync.mjs` и `scripts/check-sync.spec.mjs`.
- Строка «Автоприёмка» в `state.md` пишет `scripts/accept.sh` (числа тестов из отчётов Vitest); руками не править.
