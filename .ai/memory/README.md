# Память проекта для AI

Проект — только backend (frontend — отдельный репозиторий `messenger-client-react`, SH-D04). Маршрутизатор «задача → файлы» — в `CLAUDE.md`; правила работы с памятью — `.ai/rules/memory-protocol.md`.

```
.ai/memory/
  README.md              # этот файл
  decisions.md           # генерируемый индекс решений (SH-Dxx — сквозные, BE-Dxx — backend)
  decisions/<тема>.md    # тексты решений по темам (9 тем, SH-D23)
  product-agreements.md  # соглашения по продукту и бэкенду
  state.md  tasks.md  tasks-archive.md  architecture.md
  backlog/<ID>.md        # детали задачи из «Бэклог» (одна задача — один файл)
  archive/<слаг>.md      # закрытая задача целиком; tasks-archive.md — индекс (BE-62)
```

## Файлы
| Файл | Что хранит | Когда читать | Как обновлять |
|---|---|---|---|
| tasks.md | В работе (одна задача с контрактом, `.ai/rules/workflow.md`) / Бэклог | всегда при задаче разработки | Бэклог — одна строка `- **BE-NN (P?)** название` ≤ 200 символов, детали в `backlog/<ID>.md`; при старте задачи файл удаляется; без секции «В работе» файл ≤ 5 000 байт (проверяет `check-sync.mjs`); закрытую — в архив |
| backlog/<ID>.md | Полный текст задачи из бэклога (критерии, зависимости, контекст) | при выборе или старте задачи | Создавать вместе со строкой в бэклоге; удалять при переносе в «В работе» |
| tasks-archive.md | Индекс закрытых задач: строка `- ГГГГ-ММ-ДД — [слаг](archive/слаг.md): суть`, суть ≤ 100 символов, файл ≤ 8 КБ | `grep` по ID или теме, затем нужный файл | Только добавлять, новые строки сверху; пару «строка ↔ файл», дубли и порядок дат проверяет `check-sync.mjs` |
| archive/<слаг>.md | Закрытая задача: дата, результат, приёмка, ревью | по ссылке из индекса | Создавать при закрытии вместе со строкой индекса; не менять |
| state.md | Текущее состояние, известные проблемы (с путями к коду), последняя приёмка, фокус | баги, регрессии, выбор следующей задачи | Перезаписывать целиком только после сверки с кодом |
| architecture.md | Карта модулей, потоки данных, схема БД | новые модули, правка структуры/схемы | Править при изменении структуры |
| product-agreements.md | Цель, рамки и соглашения по продукту, архитектуре и бэкенду | проектирование контракта API/событий, реалтайм, серверное хранение | Менять только по решению пользователя (запись в `decisions/<тема>.md`) |
| decisions.md | Индекс решений: ID, суть, статус, файл темы (генерируется `node scripts/decisions-index.mjs`, ручная правка заблокирована `protect.mjs`; `check-memory.sh` сверяет с темами) | процесс/память, архитектурный выбор, новая технология — найти ID/тему в индексе | Не править; пересобирать скриптом |
| decisions/<тема>.md | Тексты решений: что, почему, альтернативы (`SH-Dxx`, `BE-Dxx`); темы: process, harness, stack, access-auth, auth-password, sessions-limits, chats-messages, realtime, superseded | только нужная тема или `grep -n -A12 '^## BE-Dxx' .ai/memory/decisions/*.md`, не целиком | Новое решение — в конец файла темы, затем пересобрать индекс; заменённое целиком переносится в `superseded.md` |

Контракт auth для этого проекта задан на стороне frontend: файл auth-contract.md в памяти репозитория `messenger-client-react` (`/home/mako/Projects/react/messenger-client-react/.ai/memory/auth-contract.md`). Своего `contracts.md` нет — контракты API/событий проектируются здесь (BE-03).

## Правила актуальности и корректности
- Первая строка после заголовка в `state.md`, `tasks.md`, `architecture.md`: `> Проверено: ГГГГ-ММ-ДД @ <git sha>[+dirty]` — дата и коммит, на которых факты сверены с кодом. Без git — `@ no-git`. Пишет **только** `scripts/stamp-memory.mjs` после успешной `bash scripts/check-memory.sh`; ручная правка заблокирована `scripts/hooks/protect.mjs` (SH-D19).
- Каждое утверждение о проблеме/состоянии содержит путь к коду в обратных кавычках и проверено чтением кода, `grep` или запуском — не по памяти и не по прошлой записи.
- Исправленное из «Известных проблем» удаляется (история — в git и `archive/`).
- Задача в «В работе» содержит контракт с блоком «Осталось» (проверяет `scripts/check-sync.mjs`); запись в архиве — дату и результат приёмки.
- ID: задачи `BE-NN`, решения `BE-DNN` / `SH-DNN`. ID не переиспользуются (в том числе после удаления задачи).
- Даты — абсолютные `ГГГГ-ММ-ДД`. Не хранить секреты и то, что очевидно из кода/git.
- Механическая проверка: `bash scripts/check-memory.sh` (входит в `bash scripts/accept.sh`). Она же запускает `scripts/check-sync.mjs`: **код — источник истины**, любое расхождение кода со спекой ядра (`docs/contract.md`), `docs/client-integration.md`, `architecture.md`, `.env.example`, ссылками на `BE-Dxx`/`SH-Dxx`/`BE-NN` — ошибка, приёмка не проходит. Меняешь маршрут, код ошибки, переменную окружения, WS-событие, схему БД, DTO или лимит — правь код и документы в одной задаче. Среди проверяемых фактов — коды `error.details[].code` (тип `ValidationCode` в `src/common/app-error.ts` против таблицы подраздела «Коды details» в `docs/client-integration.md` §1.3). Добавил новый вид фактов, которые должны совпадать, — расширь `scripts/check-sync.mjs` и `scripts/check-sync.spec.mjs`.
- Строка «Автоприёмка» в `state.md` пишет `scripts/accept.sh` (числа тестов из отчётов Vitest); руками не править.
