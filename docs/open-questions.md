## Блокировали закрытие BE-D15 (решены)
1. **Код `already_exists`** для дубля записи в allowlist (`POST /api/admin/allowlist` → 409). В спеке для дубля указан только статус `409`; код `already_exists` ввёл исполнитель, подтверждения пользователя нет (ответ «хорошо» относился к сообщению с двумя вопросами).
2. **Имя кода `login_taken`** для случая «известный пользователь сменил логин/email на тот, что в allowlist привязан к другому аккаунту» (редирект `/?auth_error=login_taken`, REST-код 409). Имя выбрал исполнитель; смысл («логин/email занят») задан пользователем.

## Принятые исполнителем допущения (подтвердить или отклонить)
4. **`FIRST_ADMIN` из конфигурации применяется, только пока в БД нет ни одного админа** (BE-D15). Цена: если единственный админ пропадёт, нужен ручной сброс в БД. Админов пока нельзя назначать через API.
5. **Google: логин в allowlist = подтверждённый email** (BE-D11, подтверждено), имя без `name` — `given_name`, иначе «Пользователь» (BE-D12, подтверждено). Не подтверждалось отдельно: что email у Google можно сменить, и для таких людей работает привязка по `sub` (BE-D15).
