# Аудит AI-харнеса messenger-server (2026-10-12)

Источники: курс «Claude Code PRO» (`github.com/justxor/claude-code-pro-course`) и курс «Harness Engineering» (`github.com/justxor/Harness_ru`; хвост README с разделами «40 техник» и «каталог антипаттернов» не прочитан). Цель: работа над задачами с минимальным расхождением с постановкой, без лишних токенов и итераций.

## 1. Применимые идеи из источников
1. Пять подсистем харнеса: инструкции, инструменты, окружение, состояние, обратная связь. Строить начиная с обратной связи.
2. Правило в тексте — просьба. Критичное переводится в hook, `permissions.deny`, линтер или скрипт; текст после этого удаляется.
3. Контракт задачи до кода: цель, проверяемые критерии, «вне рамок», команда проверки.
4. WIP = 1: одна активная задача, найденное по пути — в бэклог.
5. Готовность определяется кодом выхода команды; оценщик работает в чистом контексте.
6. У цикла есть лимит попыток: одна проверка падает три раза подряд — остановка и отчёт.
7. Токены: короткий корневой файл, подгрузка по требованию, состояние на диске, `/clear` между задачами, передача работы примерно на 60% контекста.
8. Повторяющееся замечание ревью превращается в проверку, текст из инструкций удаляется.

Не применяется (избыточно для одного разработчика): `feature_list.json` (его роль выполняет строка «Автоприёмка» от `scripts/accept.sh`), бенчмарки и абляции, graph engineering, параллельные worktree-агенты, плагины и маркетплейсы.

## 3. Найденные проблемы
1. **Глобальные агенты и скиллы противоречат проекту.** `~/.claude/agents/nestjs-engineer.md` и `nestjs-reviewer.md` подгружают скилл `project-memory` (15 КБ) с раскладкой `.ai/memory/backend/` и `contracts.md`, которых в проекте нет. Скилл и `nestjs-engineer` требуют спрашивать о записи решения после реализации, а `.ai/rules/tech-approval.md` — до реализации и сразу записывать. `task-planner` пишет в `.ai/memory/frontend/tasks.md`, `solution-architect` читает `.ai/memory/frontend/architecture.md` и использует `FE-DNN`. Агенты упоминают Jest, проект использует Vitest.
2. **Устаревшие факты.** `CLAUDE.md` п.7 и `state.md` (проблема №1) утверждают, что remote не настроен; на деле есть `origin`, `develop` и `feature/*`.
3. **Нет контракта задачи.** Задачи в `tasks.md` без критериев приёмки, «вне рамок» и команды проверки; ревьюеру не с чем сверять результат. Планы superpowers занимают 21–45 КБ.
4. **Правила без проверок.** Prettier объявлен в `code-style.md`, но `prettier --check` находит 72 неотформатированных файла. Запреты на правку миграций, секретов и строки «Автоприёмка» существуют только в тексте. Каталога `.claude/` в проекте нет.
5. **Только тяжёлая обратная связь.** Есть лишь `accept.sh` (Docker, миграции, 229 e2e-тестов); быстрой проверки для внутреннего цикла нет.
6. **Токены.** Старт задачи читает `tasks.md` целиком (18 КБ, из них 9 КБ — «Сделано»). Глобальный `nestjs-reviewer` велит читать `decisions.md` (64 КБ) при каждом ревью. Маршрутизатор продублирован в `CLAUDE.md` и `.ai/README.md`.

## 4. План изменений
1. **Агенты.** Проектные `.claude/agents/nestjs-engineer.md`, `nestjs-reviewer.md`, `task-planner.md`, `solution-architect.md` без скилла `project-memory` и с путями проекта; глобальные агенты и скилл `project-memory` — обобщить (пути брать из маршрутизатора проекта) отдельной задачей.
2. **Контракт и WIP = 1.** `.ai/rules/workflow.md` (контракт: Цель, Критерии приёмки, Вне рамок, Затрагивает, Проверка, Осталось; лимит три попытки; передача работы при ~60% контекста). В `scripts/check-memory.sh` — проверка: в «В работе» не больше одной задачи, у неё есть «Критерии приёмки», «Вне рамок», «Проверка».
3. **Быстрая проверка.** `scripts/check-fast.sh`: `npm run lint`, `tsc --noEmit`, `vitest related` по изменённым файлам.
4. **Hooks и права.** Отдельный коммит `npm run format`. Затем `.claude/settings.json`: allow для проектных команд, ask для `npm install`, `prisma migrate`, `git push`, deny для `.env` (не `.env.*`, иначе блокируется `.env.example`). Hooks на node (`jq` не установлен): `scripts/hooks/session-brief.sh` (SessionStart — сводка «В работе», автоприёмка, фокус), `scripts/hooks/protect.mjs` (PreToolUse — секреты, применённые миграции, строка «Автоприёмка»), `scripts/hooks/format.mjs` (PostToolUse — Prettier для `src/` и `test/`), `scripts/hooks/stop-gate.mjs` (Stop — `check-memory.sh` при изменённом коде).
5. **Токены.** «Сделано» — в `.ai/memory/tasks-archive.md` (в `tasks.md` последние записи), `scripts/check-sync.mjs` ищет ID задач в обоих файлах (с тестом). Маршрутизатор — только в `CLAUDE.md`, `.ai/README.md` ссылается на него.
6. **Ratchet ревью.** `.ai/rules/review-checklist.md` с повторявшимися замечаниями (RED-тесты, границы лимитов, `.max()` у массивов, `z.infer` для DTO, согласованные чтения в транзакции, страховочные ветки ошибок, `app?.close()`); ревьюер выдаёт блок «Механизировать».
7. **Git-flow** (`.ai/rules/git-flow.md`, BE-02, правка `CLAUDE.md` п.7 и `state.md`) — после решения пользователя.

## 6. Оговорки
- Порог «60% контекста» — эвристика без измерений на задачах проекта.
- Stop-hook с `check-memory.sh` (около 1,7 с) срабатывает при каждом ответе с изменённым кодом; при помехах ослабить до предупреждения.
- Слоёв планирования несколько (`system-analyst`, `solution-architect`, superpowers); для каждой задачи выбирается один по её размеру.
